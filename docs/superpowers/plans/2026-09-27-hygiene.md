# Repo Hygiene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recorded, repeatable schema migrations (`tri migrate`), a SELECT-only role under the agents' SQL tool, a minimal environment for the MCP subprocesses, TypeScript strict mode, and a GitHub Actions workflow that runs every merge check against a real Postgres.

**Architecture:** `tri_core.db.migrate` discovers `migrations/*.sql`, back-fills a hand-migrated database by probe, then runs each pending file and its `schema_migrations` row in one transaction. `tri migrate` wraps it and then creates LangGraph's tables, replacing `scripts/setup_checkpointer.py` and the loop in `setup.sh`. Migration 010 creates `tri_reader`; every `make_query_tool` caller passes `readonly_url(settings)`. `tri_core.mcp.env.child_env` builds the subprocess environment from a five-key passthrough plus `ServerSpec.env`. CI runs the same checks as the README.

**Tech Stack:** Python 3.12, psycopg 3.3, Typer, LangGraph Postgres checkpointer and store, pytest; TypeScript 5.9 (`tsc -b`), Vite, Vitest; GitHub Actions (`actions/checkout@v7`, `actions/setup-node@v7`, `astral-sh/setup-uv` v10.1.0), Postgres 16.

**Spec:** `docs/superpowers/specs/2026-09-24-hygiene-design.md`

## Global Constraints

- CI host: GitHub Actions on `paradigmbrian/triathlon-agent`, one workflow, Postgres 16 as a service container.
- Migration tracking: a `tri migrate` command in tri-core with a `schema_migrations` table; no new dependency.
- SQL tool role: `tri_reader` with SELECT only; the tool connects with `TRI_READONLY_DATABASE_URL`, derived from `DATABASE_URL` (user and password replaced by `tri_reader` / `tri_reader`) when unset.
- The lexical check (`validate_select`) and `conn.read_only = True` stay as a second layer.
- TypeScript: `"strict": true` in `web/tsconfig.app.json` and `web/tsconfig.node.json`; errors are fixed in source, never with `!` non-null assertions or `any`.
- MCP subprocess environment: `PATH`, `HOME`, `TMPDIR`, `LANG`, `LC_ALL` (when set) plus `ServerSpec.env`, nothing else from `os.environ`.
- `scripts/setup_checkpointer.py` is deleted; `tri migrate` creates the checkpointer and Store tables as its last step.
- `tri migrate [--test] [--dry-run]`: one line per migration, `up to date` when none, exit 1 on a `MigrationError` or an unreachable database; running it twice is a no-op.
- A sha mismatch message reads exactly `migrations/<file> was edited after it was applied (recorded <sha8>, file <sha8>)`.
- A permission error from the role is returned as `{"error": "rejected: not permitted for the read-only role"}`.
- Hand-applied files (001 to 008) are back-filled by probe only on a database with nothing recorded; files after 008 always run.
- CI: `LANGSMITH_TRACING=false`, no secrets, Playwright not run, and the job fails when pytest skips anything other than the `--live` tests.
- **Brian's database rule:** the implementer never runs `tri migrate`, `psql` DDL or any write against `tri_analyze` or `tri_analyze_test` outside the test suite. Steps that need a migrated database print the command for Brian to run and wait.

## Deviations from the spec (decided while planning, 2026-09-27)

1. **`apply_migrations` takes a connection, not a URL:** `apply_migrations(conn, migrations, *, probes=PROBES, dry_run=False, log=print)`. `tri migrate` passes an autocommit connection, so each file is a real transaction. Tests pass the rolled-back `db` fixture, so each file becomes a savepoint and nothing is committed to the test database. That replaces the spec's "scratch schema created and dropped", which would have committed DDL.
2. **LangGraph tables live in `ensure_langgraph_tables(url)`,** called by the CLI after `apply_migrations` and skipped on `--dry-run`. `apply_migrations` stays synchronous and testable on the fixture connection.
3. **`pending()` is replaced by `plan(conn, migrations, probes) -> (record, run)`,** which returns both lists the dry run prints.
4. **Probe for 003 is `training_plans.targets`,** not `plan_weeks.targets`. 003 renames `training_plans.skeleton`, and `setup.sh` already probes that column.
5. **`alter default privileges in schema public ...` omits `for role tri_analyze`.** It then applies to whichever role runs the migration: the same role today, and no hard-coded owner name.
6. **The `pg_terminate_backend` test targets the owner connection's pid, not `pg_backend_pid()`.** Postgres lets any role terminate its own backend, so the spec's version would terminate the test's own connection instead of failing.
7. **The role's INSERT refusal is tested on a direct `tri_reader` connection after `set transaction read write`.** Postgres checks read-only transactions before table privileges, so through `run_readonly_query` the transaction flag always answers first.
8. **The deps field is renamed, not added.** `db_url` on the planning, nutrition and coach deps is used only by the SQL tool, so it becomes `readonly_db_url`. Five existing constructors change mechanically: two conftests, `test_fuel_node.py`, `test_design_node.py`, and `tri_coach/testing.py`.
9. **The CI skip guard checks skip reasons, not a count.** Any `SKIPPED` line not ending in `needs --live` fails the job, so adding a live test does not need a workflow edit.
10. **Node 24 in CI,** matching the development machine (`node -v` is v24.19.0) and `setup-node@v7`'s own examples. The spec said 22.
11. **TypeScript strict needs no source fixes.** `tsc -p tsconfig.app.json --strict --noEmit` reported 0 errors on 2026-09-27, and so did the node project. The task is the config change plus the checks.
12. **One plan, not two.** The TypeScript half is a two-line config change, so plan 02 would be the CI workflow alone. It is Task 7 here.
13. **`setup.sh` is in scope.** It was written after the spec as the interim migration loop, and its header says it becomes `uv run tri migrate && uv run tri migrate --test`.
14. **Two existing tests change text:** `test_setup_hints_keep_todays_text` (tri-core) and `test_ready_names_the_missing_piece` (tri-coach) assert the old `scripts/setup_checkpointer.py` hint. They are updated to the new hint, and neither assertion is weakened.

## Review Focus

- **A database migrated by `setup.sh` (001 to 007 present, no `schema_migrations`):** the first `tri migrate` must record 001 to 007 without running them, then run 009 and 010. Re-running 003 would fail on the missing `skeleton` column. Test: `test_a_hand_migrated_schema_is_recorded_without_rerunning` (Task 1).
- **The guardrails spec's 008 arrives after 009 and 010 are recorded:** it must run, not be skipped as "older than the newest recorded" or back-filled by its probe. Test: `test_a_lower_version_added_later_still_runs` (Task 1).
- **`TRI_READONLY_DATABASE_URL` unset but `DATABASE_URL` carrying a query string or no password (`?sslmode=require`, `postgresql://localhost/x`):** the derived URL must keep host, port, database and query. Tests: the `reader_url` cases (Task 3).
- **The main database migrated but the test database not (or the reverse):** the role exists cluster-wide, but grants are per database. The role tests must skip on a database without 010's grants rather than fail. Test: the `reader` fixture probes `has_schema_privilege` (Task 3).
- **CI without the developer's `.env`:** `Settings()` reads `.env` locally, so a test that passes only because `.env` sets a value (the environment-dependent test hit before) fails in CI. The first workflow run is the check (Task 7). A failure there is fixed in the test's setup, not by adding secrets.

Create `packages/tri-core/src/tri_core/db/migrate.py`:

```python
"""Schema migrations: `migrations/*.sql` applied in version order and recorded in
`schema_migrations`. `tri migrate` is the only caller outside tests.

A database migrated by hand before this existed has no record; the first run detects each
hand-applied file by a probe (a table or column it creates) and records it without running it.
"""

from __future__ import annotations

import asyncio
import hashlib
import re
from collections.abc import Callable, Mapping
from dataclasses import dataclass
from pathlib import Path
from typing import Any

import psycopg
from langgraph.checkpoint.postgres.aio import AsyncPostgresSaver
from langgraph.store.postgres.aio import AsyncPostgresStore
from psycopg.rows import tuple_row

# packages/tri-core/src/tri_core/db/migrate.py -> the repository root
MIGRATIONS_DIR = Path(__file__).resolve().parents[5] / "migrations"

TRACKING_DDL = """\
create table if not exists schema_migrations (
  version     int primary key,
  name        text not null,
  sha256      text not null,
  applied_at  timestamptz not null default now()
);"""


def _table(name: str) -> str:
    return f"select to_regclass('{name}') is not null"


def _column(table: str, column: str) -> str:
    return (
        "select exists (select 1 from information_schema.columns where table_schema = "
        f"current_schema() and table_name = '{table}' and column_name = '{column}')"
    )


# What each hand-applied migration creates; present means applied. Consulted only when nothing
# is recorded yet; files after 008 have no probe and always run.
PROBES: dict[int, str] = {
    1: _table("workouts"),
    2: _table("training_goals"),
    3: _column("training_plans", "targets"),
    4: _table("nutrition_targets"),
    5: _table("lab_panels"),
    6: _column("lab_results", "bound"),
    7: _table("garmin_activities"),
    8: _column("plan_weeks", "violations"),
}

_NAME = re.compile(r"^(\d+)_\w+\.sql$")

Log = Callable[[str], None]


@dataclass(frozen=True)
class Migration:
    version: int  # leading integer of the filename
    name: str  # filename without extension
    path: Path
    sha256: str  # of the file's bytes

    @property
    def sql(self) -> str:
        return self.path.read_text(encoding="utf-8")


class MigrationError(RuntimeError):
    """A migration set that cannot be applied as it stands; the message names the file."""


def discover(directory: Path = MIGRATIONS_DIR) -> list[Migration]:
    """Every `<number>_<words>.sql` in `directory`, sorted by number."""
    found: dict[int, Migration] = {}
    for path in sorted(directory.glob("*.sql")):
        m = _NAME.match(path.name)
        if not m:
            raise MigrationError(f"{path.name}: name must be <number>_<words>.sql")
        version = int(m.group(1))
        if version in found:
            raise MigrationError(
                f"{found[version].path.name} and {path.name} share version {version}"
            )
        sha = hashlib.sha256(path.read_bytes()).hexdigest()
        found[version] = Migration(version, path.stem, path, sha)
    return [found[v] for v in sorted(found)]


def applied(conn: psycopg.Connection[Any]) -> dict[int, str]:
    """version -> sha256 of every recorded migration; {} when the table is missing."""
    cur = conn.cursor(row_factory=tuple_row)
    row = cur.execute("select to_regclass('schema_migrations')").fetchone()
    if row is None or row[0] is None:
        return {}
    rows = cur.execute("select version, sha256 from schema_migrations").fetchall()
    return {int(v): str(s) for v, s in rows}


def _probe(conn: psycopg.Connection[Any], sql: str) -> bool:
    row = conn.cursor(row_factory=tuple_row).execute(sql).fetchone()
    return bool(row and row[0])


def plan(
    conn: psycopg.Connection[Any],
    migrations: list[Migration],
    probes: Mapping[int, str] = PROBES,
) -> tuple[list[Migration], list[Migration]]:
    """(record, run): files to record as applied by hand without running them, and files to run,
    each in version order. Raises MigrationError when an applied file was edited."""
    recorded = applied(conn)
    for m in migrations:
        if m.version in recorded and recorded[m.version] != m.sha256:
            raise MigrationError(
                f"migrations/{m.path.name} was edited after it was applied "
                f"(recorded {recorded[m.version][:8]}, file {m.sha256[:8]})"
            )
    todo = [m for m in migrations if m.version not in recorded]
    if recorded:
        return [], todo
    record = [m for m in todo if m.version in probes and _probe(conn, probes[m.version])]
    return record, [m for m in todo if m not in record]


def _insert(conn: psycopg.Connection[Any], m: Migration) -> None:
    conn.execute(
        "insert into schema_migrations (version, name, sha256) values (%s, %s, %s)",
        (m.version, m.name, m.sha256),
    )


def apply_migrations(
    conn: psycopg.Connection[Any],
    migrations: list[Migration],
    *,
    probes: Mapping[int, str] = PROBES,
    dry_run: bool = False,
    log: Log = print,
) -> list[Migration]:
    """Record the hand-applied files, then run each pending file and insert its row in one
    transaction. Pass an autocommit connection: each `conn.transaction()` is then a real
    transaction, so a failing file rolls back alone and earlier ones stay recorded. (On a
    connection already inside a transaction they are savepoints; the tests rely on that.)
    Returns the files run, or on a dry run the files that would run."""
    record, run = plan(conn, migrations, probes)
    if dry_run:
        for m in record:
            log(f"would record {m.name} (already applied by hand)")
        for m in run:
            log(f"would apply {m.name}")
    else:
        with conn.transaction():
            conn.execute(TRACKING_DDL)
            for m in record:
                _insert(conn, m)
        for m in record:
            log(f"recorded {m.name} (already applied by hand)")
        for m in run:
            try:
                with conn.transaction():
                    conn.execute(m.sql)
                    _insert(conn, m)
            except psycopg.Error as exc:
                raise MigrationError(
                    f"migrations/{m.path.name} failed and was rolled back: {exc}"
                ) from exc
            log(f"applied {m.name}")
    if not record and not run:
        log("up to date")
    return run


async def _langgraph_setup(url: str) -> None:
    async with AsyncPostgresSaver.from_conn_string(url) as saver:
        await saver.setup()
    async with AsyncPostgresStore.from_conn_string(url) as store:
        await store.setup()


def ensure_langgraph_tables(url: str) -> None:
    """LangGraph's checkpoint and Store tables; both setups are idempotent."""
    asyncio.run(_langgraph_setup(url))
```

@app.command()
def migrate(
    test: bool = typer.Option(False, help="Migrate TEST_DATABASE_URL instead of DATABASE_URL"),
    dry_run: bool = typer.Option(False, help="Print what would run; change nothing"),
) -> None:
    """Apply migrations/*.sql in order, record each in schema_migrations, then create LangGraph's
    checkpoint and store tables. Running it twice is a no-op."""
    settings = get_settings()
    url = settings.test_database_url if test else settings.database_url

    def out(m: str) -> None:
        console.print(m, markup=False, highlight=False)

    try:
        migrations = discover()
        with psycopg.connect(url, autocommit=True) as conn:
            apply_migrations(conn, migrations, dry_run=dry_run, log=out)
        if not dry_run:
            ensure_langgraph_tables(url)
            out("checkpoint and store tables ready")
    except (MigrationError, psycopg.Error) as exc:
        console.print(str(exc), style="red", markup=False, highlight=False)
        raise typer.Exit(code=1) from exc

-- tri_reader: the login the agents' query_training_db tool uses (tri_core.config.readonly_url).
-- SELECT only, read-only transactions by default, a 5 s statement timeout, and no
-- pg_signal_backend, so it cannot cancel or terminate another role's backend. Roles are

    create role tri_reader login password 'tri_reader' nosuperuser nocreatedb nocreaterole noinherit;
  end if;
end $$;

revoke all on schema public from tri_reader;
grant usage on schema public to tri_reader;
grant select on all tables in schema public to tri_reader;
alter default privileges in schema public grant select on tables to tri_reader;
alter role tri_reader set default_transaction_read_only = on;
alter role tri_reader set statement_timeout = '5s';

```python
"""The environment an MCP server subprocess starts with."""

from __future__ import annotations

import os

from tri_core.mcp.servers import ServerSpec

# uvx needs PATH and HOME (the Garmin server's tokens live in ~/.garminconnect); TMPDIR and the
# locale keep temp files and text encoding the same as the parent's.
PASSTHROUGH = ("PATH", "HOME", "TMPDIR", "LANG", "LC_ALL")


def child_env(spec: ServerSpec) -> dict[str, str]:
    """The passthrough keys that are set, then spec.env on top. Nothing else from os.environ:
    the servers never see the Anthropic key, the database URLs or the LangSmith key."""
    env = {k: os.environ[k] for k in PASSTHROUGH if k in os.environ}
    return {**env, **spec.env}
```
